## 三、技能主文件 SKILL.md

**每个技能目录内都有一份 `SKILL.md`，这是该技能的完整体系说明书。**

AI 工具识别一个技能，读的就是这份文件。它不只是一段元信息，而是把整套技能讲全：这个技能是干什么的、分几层几门、每层对应什么术或方法、按什么规则推演、依据哪些资料、哪些事能做哪些不能做、结果怎么输出。

因此 `SKILL.md` 必须写全下面几项：

| 项目 | 要求 |
| --- | --- |
| 技能名称与触发描述 | YAML 头部的 `name` 与 `description`，描述要能让 AI 准确判断何时调用 |
| 定位与原则 | 一句话讲清技能是什么，以及必须遵守的最高原则 |
| 体系与分层 | 完整列出内部板块、层级、门类，说明各自解决什么问题、深度到什么档位 |
| 执行流程 | 从接收请求到输出结果的每一步，含前置校验与路由判定 |
| 规则与依据 | 判断依据来自哪里（规则库、原文库、脚本），冲突时以谁为准 |
| 输出规范 | 结果的呈现结构、术语解释方式、必须标注的声明 |
| 能力边界 | 明确不做什么、超出范围时怎么回应、安全红线在哪 |

`SKILL.md` 与 `README.md` 分工不同，两者都要有：

| 文件 | 读者 | 内容侧重 |
| --- | --- | --- |
| `SKILL.md` | AI 工具 | 完整技能体系：分层、流程、规则、依据、边界、输出 |
| `README.md` | 人 | 快速了解：用途、覆盖范围、调用方式、能力边界 |

缺 `SKILL.md` 的技能不予入库。`SKILL.md` 写得笼统、撑不起整套体系的，视为未完成。

## 四、目录与命名规范

### 层级

只有两层：`一级分类 / 技能目录`。不设二级分类，避免空壳目录套娃。

**唯一例外**：`提示词/` 分类允许三层，即 `提示词/<用途分类>/<提示词目录>/`。提示词数量多、用途杂，平铺会乱，因此按用途分组。提示词目录内使用 `PROMPT.md` + `README.md`，不使用 `SKILL.md`。

### 命名

1. 一级分类用中文领域名，四个字以内，见名知意；
2. 技能目录用「中文名-范围后缀」格式，中划线分隔，后缀概括该技能覆盖的板块或数量的量词；
3. 目录名一律中文，不使用拼音缩写、不使用英文；
4. 一个技能就是一个完整技能包，内部不再拆分。覆盖范围写在名字后缀、`SKILL.md` 与目录内 `README.md` 里，不靠拆目录表达。

示例：

```text
国学占卜/综合占卜-八层卜术/     # 不拆成 命/卜/相 三个目录
国学占卜/梅花易数-四法十八类/   # 四法指起卦法，十八类指占断类目
```

### 技能目录内部结构

```text
<一级分类>/<技能名-范围后缀>/
├── SKILL.md        # 必需。完整技能体系说明书，AI 读这份
├── README.md       # 必需。面向人的说明：做什么、覆盖什么、怎么用、边界在哪
├── LICENSE         # 可选。与根目录授权不同时才需要
└── ...             # 脚本、规则库、原文库、模板等资源
```

## 五、安装使用

克隆整个仓库：

```bash
git clone https://github.com/ycc77cn/skills.git
```

按需把技能目录复制到所用 AI 工具的技能目录：

| 工具 | 技能目录 |
| --- | --- |
| Trae | `~/.trae-cn/skills/` 或项目内 `.trae/skills/` |
| Claude Code | `~/.claude/skills/` 或项目内 `.claude/skills/` |

示例，取梅花易数：

```bash
cp -r "skills/国学占卜/梅花易数-四法十八类" ~/.trae-cn/skills/meihua-yishu
```

因为技能目录带中文名，复制时建议指定目标目录名，避免工具侧识别异常。

## 六、贡献与收录

### 6.1 新增技能流程

1. 确认 `SKILL.md` 完整，能讲清整套体系，`description` 能准确触发；
2. 在一级分类下建「中文名-范围后缀」目录，整包放入，不拆内部结构；
3. 补齐该目录的 `README.md`，写清用途、范围、用法、边界；
4. **按 6.2 同步更新四处 README**；
5. 确认无第三方版权内容、无付费版内容混入。

### 6.2 README 同步更新（硬性要求）

**技能入库与 README 更新必须在同一次提交里完成。不允许先传技能后补文档，也不允许文档滞后于仓库内容。**

每入库一个技能，下面四处必须同步改：

| 位置 | 更新内容 |
| --- | --- |
| `README.md` | 技能清单表增加一行：技能名、目录链接、覆盖范围、状态 |
| `README_EN.md` | 英文清单表增加同一行，内容与中文版逐项对应 |
| `<一级分类>/README.md` | 该分类的「本分类包含」表增加一行，同步状态 |
| `<技能目录>/README.md` | 补齐用途、覆盖范围、调用方式、能力边界四段 |

提交前核对三条：

1. 中英两版清单的技能数量、目录路径、状态标注必须完全一致；
2. 状态从 `待迁入` 改为 `已入库` 时，四处同时改，不留任何一处旧状态；
3. 用 `git diff --stat` 自检，README 没有对应改动的提交视为不合格，不予推送。
