# 代码备份 ZIP 归档（备份）

代码修改前的备份规则手册。规定备份要放在哪、叫什么名字、排除什么、什么时候必须做。

## 技能定位

两个备份技能配合使用：

| 技能 | 角色 | 管什么 |
| --- | --- | --- |
| **代码备份-ZIP归档** | 规则版 | 备份目录、命名格式、排除项、执行时机（改码前必须备份） |
| 自动备份-永不删除 | 执行版 | 改码后自动执行、内容总结命名、永不删除备份 |

本技能是纪律层，规定"必须备份"和"怎么备份"；执行版是执行器，负责自动落地。

## 触发场景

- 任何涉及修改代码的操作开始前
- 新增、删除、移动代码文件前

## 规则细则

| 项 | 规则 |
| --- | --- |
| 备份目录 | 当前项目**根目录**下的 `beifen/`（不是项目内部子目录，是根） |
| 文件格式 | `.zip`，标准压缩格式 |
| 命名格式 | `年-月-日_时-分-秒_操作说明`，例如 `2026-01-29_12-52-15_修改XXX接口参数.zip` |
| 执行时机 | **改码前**必须备份，先备份再改 |
| 排除项 | 依赖库（node_modules 等）、编译产物（pyc 等）、非代码文件一律排除 |
| 备份范围 | 目录中的所有代码文件，不含编译产物和依赖 |

## 与执行版的配合

- 规则版管"纪律"：必须备份，改码前做
- 执行版管"自动"：改码后自动补一份，永不删除
- 建议两个技能一起装，规则版做改码前的安全垫，执行版做改码后的自动补

## 使用示例

```
项目根目录/
├── src/
├── package.json
├── beifen/                          ← 所有备份放这里
│   ├── 2026-01-29_12-52-15_修改接口参数.zip
│   ├── 2026-01-30_09-03-22_新增导出功能.zip
│   └── 2026-02-01_18-45-10_重构数据层.zip
```
