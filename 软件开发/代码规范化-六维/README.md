# 代码规范化 六维体系（code-refactor-spec）

对任意编程语言代码做全维度规范化，支持「重构」与「写代码」两种模式，覆盖代码本体、文件目录、注释、接口命名、工程规范、安全防护六个维度。

## 用途

两种模式，先判定再执行：

| 模式 | 输入 | 原则 |
| --- | --- | --- |
| 重构模式 | 已有项目或代码片段 | 只改形式，不改业务逻辑，不加功能 |
| 写代码模式 | 新需求 | 生成时直接遵循六维规范，不事后返工 |

模式判定依据：用户是否提供既有代码、是否明确要求保持行为不变。

## 覆盖范围

| 维度 | 规范内容 |
| --- | --- |
| 文件与目录 | 分层结构、模块边界、目录命名一致性 |
| 命名 | 变量、函数、类、接口的命名风格与语义要求 |
| 注释 | 中文注释、函数级说明、注释必要性与信息密度 |
| 代码格式 | 缩进、换行、行长度、空行分组 |
| 接口 | 参数、返回值、错误码、边界约定 |
| 后端安全 | 输入校验、敏感信息处理、权限边界、注入防护 |

## 执行流程

重构模式固定九步，写代码模式走简化流程。执行红线单列在前：重构模式禁止改动业务行为，写代码模式禁止跳过规范。

## 内部结构

```text
代码规范化-六维/
├── SKILL.md              # 主文件：两模式流程、六维细则、执行红线
├── checklist.md          # 自检清单，重构与写代码各一套
├── directory_rules.md    # 文件与目录规范细则
├── naming_rules.md       # 命名规范细则
├── security_rules.md     # 后端安全防护细则
├── report_template.md    # 规范化报告模板
└── README.md             # 本文件
```

## 调用方式

由 AI 工具按 `SKILL.md` 的 `description` 自动触发。典型触发语句：代码重构、代码标准化、格式整理、按规范写代码、代码审查、统一命名。

## 能力边界

1. 重构模式不改业务逻辑、不改接口语义、不擅自新增功能；
2. 不替代架构设计，不做技术选型建议；
3. 不处理与规范无关的性能优化。
