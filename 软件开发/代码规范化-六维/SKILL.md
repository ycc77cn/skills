# 标准化代码重构与生成 Skill

## 一、Skill 简介

本 Skill 是**专业代码标准化重构与生成机器人**，支持两种模式：

### 模式一：重构模式

- **接收对象**：任意编程语言的原始项目 / 零散代码片段
- **核心目标**：做全维度规范化重构，覆盖**代码本体、文件目录、注释、接口命名、工程规范、安全防护**六大模块
- **核心边界**：**不改动原有业务逻辑、算法、功能**，仅统一规范、修复格式、补齐注释、统一命名、规整文件结构、修复安全漏洞
- **最终输出**：可直接上线的干净工程代码 + 完整重构变更报告 + 安全评估报告 + 验证报告

### 模式二：写代码模式

- **接收对象**：用户需求描述 / 功能规格说明 / 接口定义
- **核心目标**：生成规范化代码，在生成时直接遵循**文件目录、注释、接口命名、工程规范、安全防护**六大模块规范
- **核心边界**：生成代码时必须符合安全规范，禁止硬编码敏感信息、禁止SQL拼接、必须有输入验证、必须有错误处理
- **最终输出**：可直接上线的标准化工程代码 + 完整规范报告 + 安全合规声明 + 验证报告

### 1.1 适用场景

| 模式 | 场景 | 触发动作 |
|------|------|----------|
| 重构模式 | 接手历史遗留项目 | 套用本 Skill 全量重构 |
| 重构模式 | 多人协作代码风格不一 | 套用本 Skill 统一规范 |
| 重构模式 | 上线前规范化整理 | 套用本 Skill 做最后一遍扫尾 |
| 重构模式 | 代码 review 前的自检 | 按本 Skill 校验清单逐条过 |
| 写代码模式 | 新模块开发 | 生成时直接遵循规范 |
| 写代码模式 | 新接口开发 | 生成安全合规的接口代码 |
| 写代码模式 | 新功能实现 | 生成规范化、安全可靠的代码 |

### 1.2 模式切换判定

| 用户输入特征 | 判定模式 |
|--------------|----------|
| 提供已有代码/项目路径 | 重构模式 |
| 提供需求描述/功能规格 | 写代码模式 |
| 明确要求"重构" | 重构模式 |
| 明确要求"生成代码"或"写代码" | 写代码模式 |

### 1.3 不适用场景

- 需要重写业务逻辑、性能优化、算法升级的任务（重构模式）
- 需要做架构级改造（如单体拆微服务）的任务

## 二、Skill 执行红线（最高优先级）

> **红线按模式区分，违反任意一条即视为失败，必须回退重做。**

### 2.1 重构模式红线

1. **不得修改业务逻辑**：不改动运算公式、判断条件、循环分支的业务含义
2. **不得简化 / 优化原有算法**：只做规范，不做性能重构
3. **不得删减原有功能分支**：所有 `if/else`、`switch/case`、`try/catch` 分支必须保留
4. **不得擅自新增业务代码 / 新增接口 / 删除原有接口**：所有对外接口签名、入参出参业务含义保持不变

**重构模式附加约束**：

- 不修改数据库查询语句的业务条件（`WHERE` 条件、连表关系等）
- 不修改接口入参出参的业务字段映射
- 不修改变量运算的业务含义
- 不引入新的第三方依赖（除非原项目已使用）

### 2.2 写代码模式红线

1. **必须符合安全规范**：生成的代码必须通过所有安全校验项（SQL注入、XSS、CSRF、输入验证等）
2. **禁止硬编码敏感信息**：密码、密钥、Token、身份证号等敏感信息必须通过环境变量或配置文件注入
3. **必须有输入验证**：所有接口输入参数必须校验（类型、长度、范围、格式）
4. **必须有错误处理**：所有异常必须捕获处理，错误响应禁止暴露技术细节
5. **必须有注释**：每个文件必须有头部注释，每个函数必须有文档注释

**写代码模式附加约束**：

- SQL查询必须使用参数化查询，禁止字符串拼接
- 密码必须使用BCrypt/Argon2哈希存储，禁止明文或弱哈希
- 日志禁止记录敏感信息（密码、Token、身份证号）
- API返回敏感字段必须脱敏
- 文件上传必须有类型白名单和大小限制

## 三、Skill 执行流程（AI 处理代码的固定 9 步）

> **流程按模式区分，重构模式9步全执行，写代码模式简化流程。**

### 3.1 重构模式执行流程（9步）

AI 接到已有代码后，**必须严格按以下顺序执行**，每一步都要有明确的输出产物：

#### 第 1 步：全量代码扫描与业务快照 + 安全隐患记录

**目标**：记录原有业务逻辑，同步记录安全隐患。

**动作清单**：

- 扫描全部源文件，列出文件清单（含路径、大小、语言类型）
- 梳理核心业务模块的入口与调用关系
- 记录所有对外接口（HTTP / RPC / 函数）的签名、入参、出参
- 记录所有数据库表 / 字段 / SQL 业务条件
- 记录所有核心常量、配置项、魔法数字
- **同步记录安全隐患**：
  - SQL拼接风险点
  - 硬编码敏感信息位置
  - 日志敏感信息位置
  - 输入未校验的接口
  - 错误响应暴露技术细节的位置
- 输出**业务快照清单**和**安全隐患清单**

**输出物**：`business_snapshot.md`（业务快照）、`security_issues.md`（安全隐患清单）

#### 第 2 步：文件目录梳理与归类 + 敏感文件隔离

**目标**：零散文件归类到对应文件夹，判定文件拆分/合并，隔离敏感文件。

**动作清单**：

- 后端项目：识别 `controller / service / model / util / config / middleware / dao / dto / vo` 等分层
- 前端项目：识别 `views / components / api / store / router / utils / assets / styles` 等分层
- 零散文件按功能归类到对应文件夹
- 删除无用空文件、临时测试文件（`test_tmp.py`、`a.txt`、`新建文本文档.txt` 等）
- **文件大小判定**：业务逻辑文件超过 500 行、工具函数超过 300 行需拆分
- **功能拆分判定**：一个文件包含多个不相关功能需拆分
- **职责分离判定**：数据定义与业务逻辑混合需拆分
- **文件合并判定**：多个文件功能高度相关且总代码 < 200 行建议合并
- **敏感文件隔离**：
  - `.env`、`config.ini`、密钥文件移到非web根目录
  - 日志文件移到独立 `logs/` 目录
  - 配置文件按环境分离到 `config/dev`、`config/prod`、`config/test`
- 输出**目录调整对照表**和**文件拆分/合并清单**

**输出物**：`directory_changes.md`（目录调整说明）、`file_split_merge.md`（文件拆分/合并清单）

#### 第 3 步：全量命名规范化与替换

**目标**：全局统一命名风格，全项目替换不冲突。

**动作清单**：

- 变量 / 函数 / 方法：英文语义化命名，禁止拼音、无注释缩写、单字母无意义变量（`a/b/tmp` 仅允许作为循环临时变量）
- 常量：全大写下划线 `MAX_RETRY_COUNT`
- 类 / 结构体 / 接口：大驼峰 `PascalCase`
- HTTP 接口：REST 风格 `动词+资源`，如 `getUserInfo`、`createOrder`、`/user/order-list`
- 数据库表 / 字段：下划线命名，语义清晰
- 混合驼峰 / 下划线全部修正为对应语言标准
- 输出**命名替换对照表**（旧名 → 新名、位置、影响范围）

**输出物**：`naming_changes.md`（命名替换对照表）

#### 第 4 步：注释补全与清理 + 敏感信息清理

**目标**：补齐缺失注释，清理垃圾注释，清理敏感信息注释。

**动作清单**：

- **文件头部**：统一文件说明注释（文件作用、创建人、核心功能、修改记录）
- **类 / 接口 / 函数**：必须添加标准文档注释
  - Python：docstring
  - Java：JavaDoc
  - TypeScript / JavaScript：JSDoc
  - Go：标准 godoc 注释
  - 标注：入参、出参、异常、业务说明
- **复杂逻辑代码块**：单行注释，解释「为什么这么写」而非「代码做了什么」
- **删除无效注释**：打印调试注释（`// console.log("test")`）、过期废弃注释、重复冗余注释
- **敏感信息清理**：
  - 删除注释中的密码、密钥、Token
  - 删除注释中的身份证号、手机号、银行卡号
  - 删除注释中的数据库连接信息
- **中文注释**：统一规范用词，杜绝口语化、错别字
- 输出**注释变更清单**

**输出物**：`comment_changes.md`（注释变更清单）

#### 第 5 步：代码格式与语法规范化 + 调试代码清理 + 暴露技术细节修复

**目标**：统一排版、缩进、空行、运算符风格，清理调试代码，修复技术细节暴露。

**动作清单**：

- 统一缩进：2 空格 / 4 空格（按语言主流风格固定），全文件对齐，删除 tab 与空格混合
- 空行统一：函数之间、逻辑块之间固定 1 行空行，连续多行空行压缩为 1 行
- 运算符前后加空格，括号、逗号格式化，统一分号 / 换行风格
- 消除魔法数字，提取为命名常量
- 统一异常捕获、返回值规范，零散 `return` 统一格式
- **调试代码清理**：
  - 删除无用 `console.log` / `print` / 临时调试代码
  - 删除调试模式开关残留代码
- **暴露技术细节修复**：
  - 错误响应统一为 `{ code, msg, data }` 结构
  - 错误信息禁止包含堆栈、SQL语句、文件路径、数据库表名
  - 异常捕获后返回通用错误信息
- 输出**格式调整清单**

**输出物**：`format_changes.md`（格式调整清单）

#### 第 6 步：接口标准化 + 输入验证补齐 + 返回体脱敏 + 限流配置

**目标**：HTTP 接口与内部函数接口全面规范化，补齐输入验证，脱敏返回体，配置限流。

**动作清单**：

- **HTTP 接口**：
  - 统一请求方法 `GET / POST / PUT / DELETE`
  - 路径小写 + 横杠 `/user/order-list`
  - 统一返回体格式：`{ code, msg, data }` 三层标准结构
  - 接口参数校验注释补齐，必填 / 选填标注
- **输入验证补齐**：
  - 所有接口输入参数校验（类型、长度、范围、格式）
  - 使用校验框架统一校验（如 Pydantic、Spring Validation）
  - 特殊字符过滤、白名单校验
- **返回体脱敏**：
  - 手机号中间4位用 `*` 代替
  - 身份证号中间8位用 `*` 代替
  - 银行卡号中间8位用 `*` 代替
  - 邮箱@前显示前2位 + `***`
- **限流配置**：
  - 普通查询接口：100次/分钟/IP
  - 登录接口：5次/分钟/IP
  - 短信验证码：1次/60秒/手机号
  - 支付接口：3次/分钟/用户
- **内部函数接口**：
  - 参数顺序统一，避免过长参数
  - 超过 3 个参数自动封装结构体 / 入参对象
  - 接口重复逻辑抽离公共工具方法
- 输出**接口变更清单**

**输出物**：`interface_changes.md`（接口变更清单）

#### 第 7 步：安全扫描与修复

**目标**：扫描安全漏洞，修复安全隐患，输出安全评估报告。

**动作清单**：

- **SQL 注入修复**：
  - 所有 SQL 查询改为参数化查询
  - ORM 查询改为预编译语句
  - 禁止字符串拼接 SQL
- **XSS 修复**：
  - 用户输入输出转义过滤
  - Cookie 设置 HttpOnly 属性
  - 富文本使用 DOMPurify 等库净化
- **CSRF 修复**：
  - 实现 CSRF Token 验证机制
  - Token 长度 ≥ 32位随机字符串
  - Token 存储在 HttpOnly Cookie 中
- **身份认证修复**：
  - 密码改为 BCrypt / Argon2 哈希存储
  - Token 设置过期时间
  - 实现最小权限原则
- **敏感数据保护修复**：
  - 日志敏感信息脱敏或删除
  - 数据库敏感字段加密
  - API 返回敏感字段脱敏
- **文件上传安全修复**：
  - 设置文件类型白名单
  - 设置文件大小限制
  - 文件存储移到非web根目录
- **安全配置修复**：
  - 禁止硬编码敏感信息
  - 调试模式关闭
  - 默认密码修改
- 输出**安全评估报告**和**安全修复清单**

**输出物**：`security_report.md`（安全评估报告）

#### 第 8 步：代码验证与运行测试

**目标**：验证重构后代码能否正常运行，确保功能一致性。

**动作清单**：

- **编译检查**：Go/Java/C++等编译型语言，执行编译命令检查语法错误
- **语法检查**：Python/JS等解释型语言，执行语法检查工具（pylint、eslint）
- **单元测试**：执行项目已有单元测试，验证核心功能
- **接口测试**：对HTTP接口执行简单测试（curl、postman），验证接口可用
- **运行测试**：启动项目，执行简单功能测试，验证基本功能
- 输出**验证报告**（成功/失败、失败原因、修复建议）

**验证方式**：

| 语言 | 验证命令 |
|------|----------|
| Python | `python -m py_compile [file]`、`pytest` |
| Go | `go build`、`go test` |
| Java | `mvn compile`、`mvn test` |
| JavaScript | `npm run lint`、`npm test` |
| TypeScript | `tsc --noEmit`、`npm test` |

**输出物**：`validation_report.md`（验证报告）

#### 第 9 步：最终交付

**交付四份内容**：

1. **完整重构后全部标准化代码 / 工程文件**（按目录结构输出）
2. **重构变更报告**（合并所有 step 的变更清单）
3. **安全评估报告**（安全风险扫描结果、安全修复清单、安全合规声明）
4. **验证报告**（编译/语法检查、单元测试、接口测试、运行测试结果）

### 3.2 写代码模式执行流程（简化流程）

AI 接到需求描述后，**直接生成规范化代码**，在生成时同步遵循以下规范：

#### 生成时同步遵循的规范

| 生成阶段 | 同步遵循的规范 | 检查点 |
|----------|----------------|--------|
| 目录设计 | 目录分层标准、文件大小限制、敏感文件隔离 | 目录结构符合规范 |
| 命名设计 | 命名风格对照表、禁用清单 | 变量、函数、类命名符合规范 |
| 注释设计 | 文件头部注释、函数文档注释、敏感信息禁止出现在注释 | 所有文件有头部注释，所有函数有文档注释 |
| 代码生成 | 格式规范、魔法数字提取、调试代码禁止 | 代码格式符合规范 |
| 接口生成 | 输入验证必须有、返回体脱敏、限流配置、错误处理 | 所有接口有输入验证，返回体脱敏 |
| 安全生成 | SQL参数化查询、密码哈希存储、日志禁止敏感信息、禁止硬编码 | 安全规范全部到位 |

#### 写代码模式输出清单

| 输出内容 | 说明 |
|----------|------|
| 标准化工程代码 | 按目录结构输出，每个文件符合规范 |
| 规范报告 | 目录设计、命名设计、注释设计、格式规范、接口规范、安全规范的执行情况 |
| 安全合规声明 | 列出所有安全规范的执行情况（✅ 已执行） |
| 验证报告 | 编译/语法检查、单元测试、接口测试、运行测试结果（如果有测试环境） |

## 四、六大模块规范细则（简版）

> 详细规则见拆分文件，本章节仅保留核心要点和引用说明。

### 4.1 文件 & 目录规范化

**核心要点**：
- 目录分层标准：controller / service / model / mapper / util / config / middleware
- 文件大小限制：业务500行、工具300行、配置100行、模型200行
- 单一职责：一个文件只做一件事
- 敏感文件隔离：.env、密钥不在web根目录

**详细规则见**：[directory_rules.md](./directory_rules.md)

### 4.2 命名规范化

**核心要点**：
- 变量/函数：小驼峰或下划线（按语言）
- 常量：全大写下划线 MAX_RETRY_COUNT
- 类：大驼峰 PascalCase
- HTTP接口：动词+资源 getUserInfo
- 禁止拼音、无意义缩写、模糊命名

**详细规则见**：[naming_rules.md](./naming_rules.md)

### 4.3 注释规范化

**核心要点**：
- 文件头部：文件作用、创建人、创建时间、修改记录
- 函数：入参、出参、异常、业务说明
- 复杂逻辑：单行注释解释「为什么」
- 禁止注释敏感信息（密码、Token、身份证号）

**注释模板**：
- Python：docstring
- Java：JavaDoc
- TypeScript/JavaScript：JSDoc
- Go：godoc

### 4.4 代码格式规范

**核心要点**：
- 缩进：4空格固定，禁止tab
- 空行：函数间2行，逻辑块间1行
- 运算符前后加空格
- 魔法数字提取为常量
- 删除调试代码（console.log、print）

### 4.5 接口规范化

**核心要点**：
- HTTP方法：GET查询、POST创建、PUT更新、DELETE删除
- 路径：小写+横杠 /user/order-list
- 返回体：{ code, msg, data } 三层结构
- 分页：{ list, total, page, page_size }
- 输入验证：类型、长度、范围校验
- 返回体脱敏：手机号、身份证号脱敏

### 4.6 后端安全防护规范

**核心要点**：
- SQL注入：参数化查询，禁止字符串拼接
- XSS：输出转义，Cookie HttpOnly
- CSRF：Token验证，长度≥32位
- 身份认证：密码BCrypt哈希，Token过期时间
- 输入验证：所有接口输入校验
- 敏感数据：日志禁止敏感信息，API返回脱敏
- 接口安全：限流、频率限制
- 错误处理：不暴露技术细节
- 文件上传：类型白名单、大小限制
- 安全配置：禁止硬编码敏感信息

**详细规则见**：[security_rules.md](./security_rules.md)
