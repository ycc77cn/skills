# 后端安全防护规范

> 本文件是 code-refactor skill 的拆分规则文件，详细定义安全防护规范。适用于重构和写代码两种模式。

---

## 一、SQL 注入防护

### 1.1 核心规则

| 规则 | 说明 | 正确示例 | 错误示例 |
|------|------|----------|----------|
| 必须使用参数化查询 | 禁止字符串拼接 SQL | `SELECT * FROM users WHERE id = %s` | `SELECT * FROM users WHERE id = ' + userId + '` |
| ORM 框架必须开启参数化 | ORM 查询也必须使用预编译 | `db.query(User).where("id", userId)` | `db.raw("SELECT * FROM users WHERE id = " + userId)` |
| 禁止动态 SQL 拼接 | 必须用白名单方式构建 | 用枚举限制表名、字段名 | 直接拼接用户输入到 SQL |
| 存储过程必须参数化 | 存储过程调用也需参数化 | `call sp_get_user(?)` | `call sp_get_user(' + userId + ')` |

### 1.2 防护层级

1. **第一层**：框架层（ORM 参数化、预编译语句）
2. **第二层**：代码层（不拼接 SQL、输入校验）
3. **第三层**：数据库层（最小权限原则、SQL 审计）

## 二、XSS（跨站脚本）防护

### 2.1 核心规则

| 规则 | 说明 | 防护措施 |
|------|------|----------|
| 输出必须转义 | 用户输入渲染到页面必须转义 | 使用框架自带的模板引擎转义 |
| 禁止 unsafe 渲染 | React 禁止 `dangerouslySetInnerHTML` | 使用 `sanitize-html` 过滤 |
| 富文本必须净化 | 富文本编辑器内容必须过滤 | 使用 DOMPurify 等库净化 |
| Cookie 必须设置 HttpOnly | 防止 JS 读取敏感 Cookie | `Set-Cookie: sid=xxx; HttpOnly; Secure` |
| 禁止内联脚本 | 禁止 `onclick`、`onload` 等内联事件 | 使用事件监听代替 |

### 2.2 输出转义规则

| 输出场景 | 转义方式 |
|----------|----------|
| HTML 标签内文本 | HTML 实体转义（`<`→`&lt;`） |
| HTML 属性值 | HTML 实体转义 |
| JavaScript 字符串 | JavaScript 转义 |
| URL 参数 | URL 编码 |
| CSS 值 | CSS 转义 |

## 三、CSRF（跨站请求伪造）防护

### 3.1 核心规则

| 规则 | 说明 | 防护措施 |
|------|------|----------|
| 必须使用 CSRF Token | 非 GET 请求必须验证 Token | 每个请求携带 `X-CSRF-Token` |
| Token 必须绑定 Session | 防止 Token 复用 | Token 存储在 Session 中 |
| 验证 Token 来源 | 验证 Referer / Origin | 拒绝非法来源请求 |
| 敏感操作二次确认 | 重要操作需再次验证身份 | 密码确认、短信验证 |

### 3.2 CSRF Token 生成规则

- 长度 ≥ 32 位随机字符串
- 每次请求刷新 Token
- Token 存储在 HttpOnly Cookie 中
- 请求时通过 Header 或 Body 携带

## 四、身份认证与授权

### 4.1 核心规则

| 规则 | 说明 | 实施方式 |
|------|------|----------|
| 必须使用强认证方式 | 禁止明文密码传输 | JWT、OAuth2、Session |
| 密码必须加密存储 | 禁止明文存储密码 | BCrypt（cost ≥ 10）、Argon2 |
| Token 必须设置过期时间 | 禁止永久有效 Token | Access Token 5-15 分钟，Refresh Token 7-30 天 |
| 必须校验 Token 有效性 | 每次请求验证 Token | 中间件统一校验 |
| 权限必须细粒度控制 | 禁止全局权限 | RBAC（角色权限控制） |
| 最小权限原则 | 禁止过度授权 | 按需分配角色和权限 |

### 4.2 密码安全规则

- 密码长度 ≥ 8 位
- 必须包含大小写字母、数字、特殊字符
- 存储时使用 BCrypt / Argon2 哈希
- 禁止使用 MD5、SHA1 等弱哈希算法
- 禁止存储密码明文或可逆加密

## 五、输入验证与过滤

### 5.1 核心规则

| 规则 | 说明 | 验证方式 |
|------|------|----------|
| 所有输入必须校验 | 禁止信任用户输入 | 参数校验框架统一校验 |
| 字段类型必须匹配 | 禁止类型转换漏洞 | 严格类型校验 |
| 字段长度必须限制 | 防止超长输入攻击 | 设置最大长度限制 |
| 特殊字符必须过滤 | 防止注入攻击 | 白名单过滤 |
| 数值范围必须校验 | 防止越界攻击 | 设置上下限 |

### 5.2 输入验证清单

| 参数类型 | 校验项 |
|----------|--------|
| 字符串 | 长度、格式、特殊字符 |
| 数字 | 范围、精度、类型 |
| 日期 | 格式、范围 |
| 邮箱 | 格式校验 |
| 手机号 | 格式校验 |
| URL | 协议校验、域名白名单 |
| 文件 | 类型白名单、大小限制 |

## 六、敏感数据保护

### 6.1 核心规则

| 规则 | 说明 | 保护方式 |
|------|------|----------|
| 禁止日志打印敏感信息 | 密码、Token、身份证号禁止出现在日志 | 使用脱敏处理 |
| 传输必须加密 | 生产环境必须 HTTPS | TLS 1.2+ |
| 数据库敏感字段必须加密 | 身份证号、手机号、银行卡号 | 字段级加密 |
| 禁止前端存储敏感信息 | 密码、Token 禁止存 localStorage | 使用 HttpOnly Cookie |
| API 返回必须脱敏 | 敏感字段返回脱敏后的值 | `138****8888`、`6222****1234` |

### 6.2 数据脱敏规则

| 数据类型 | 脱敏方式 | 示例 |
|----------|----------|------|
| 手机号 | 中间 4 位用 `*` 代替 | `138****8888` |
| 身份证号 | 中间 8 位用 `*` 代替 | `110101********1234` |
| 银行卡号 | 中间 8 位用 `*` 代替 | `6222****1234` |
| 邮箱 | @ 前显示前 2 位 + `***` | `zh***@qq.com` |

## 七、接口安全防护

### 7.1 核心规则

| 规则 | 说明 | 实施方式 |
|------|------|----------|
| 必须设置接口限流 | 防止暴力攻击和资源耗尽 | 基于 IP、用户的限流 |
| 必须设置请求超时 | 防止慢请求攻击 | 设置合理的超时时间 |
| 必须设置并发限制 | 防止并发攻击 | 基于用户或 IP 的并发数限制 |
| 必须设置请求频率限制 | 防止刷接口 | 滑动窗口限流 |
| 敏感接口必须二次验证 | 支付、修改密码等 | 短信、验证码、密码确认 |
| 必须校验请求来源 | 防止恶意请求 | 校验 Referer、Origin |

### 7.2 限流规则

| 场景 | 限制规则 |
|------|----------|
| 普通查询接口 | 100 次 / 分钟 / IP |
| 登录接口 | 5 次 / 分钟 / IP |
| 短信验证码 | 1 次 / 60 秒 / 手机号 |
| 支付接口 | 3 次 / 分钟 / 用户 |

## 八、错误处理与日志

### 8.1 核心规则

| 规则 | 说明 | 实施方式 |
|------|------|----------|
| 禁止暴露技术细节 | 错误响应不能包含堆栈信息 | 统一错误码，隐藏实现细节 |
| 禁止明文返回异常 | 数据库异常、系统异常必须脱敏 | 返回通用错误信息 |
| 日志必须结构化 | 便于日志分析和审计 | JSON 格式，包含 trace_id |
| 日志必须分级 | 区分 DEBUG / INFO / WARN / ERROR | 生产环境关闭 DEBUG |
| 必须记录敏感操作日志 | 登录、修改密码、支付等 | 记录操作人、时间、IP |
| 日志必须脱敏 | 禁止记录密码、Token、身份证号 | 敏感字段自动脱敏 |

### 8.2 错误响应规范

**正确示例**：

```json
{
  "code": 500,
  "msg": "服务器内部错误，请稍后重试",
  "data": null
}
```

**禁止返回**：

```json
{
  "code": 500,
  "msg": "SQLSyntaxError: Table 'xxx' doesn't exist",
  "data": null
}
```

## 九、文件上传安全

### 9.1 核心规则

| 规则 | 说明 | 实施方式 |
|------|------|----------|
| 文件类型必须白名单 | 禁止上传可执行文件 | 校验文件扩展名和 MIME 类型 |
| 文件大小必须限制 | 防止大文件攻击 | 设置合理的大小上限 |
| 文件存储必须隔离 | 禁止存储在 web 根目录 | 存储在独立目录或对象存储 |
| 文件访问必须鉴权 | 禁止直接访问上传文件 | 通过 API 代理访问 |
| 文件内容必须扫描 | 防止恶意文件上传 | 使用杀毒引擎扫描 |

### 9.2 文件类型白名单

| 场景 | 允许的文件类型 |
|------|----------------|
| 图片上传 | jpg、jpeg、png、gif、webp |
| 文档上传 | pdf、doc、docx、xls、xlsx |
| 视频上传 | mp4、avi、mov、wmv |

## 十、安全配置规范

### 10.1 核心规则

| 规则 | 说明 | 配置方式 |
|------|------|----------|
| 禁止使用默认密码 | 数据库、Redis 等必须修改默认密码 | 环境变量配置 |
| 禁止使用默认端口 | 非必要服务禁止使用默认端口 | 修改服务端口 |
| 禁止暴露管理端口 | 管理后台必须内网访问 | 防火墙限制 |
| 必须开启 HTTPS | 生产环境必须加密传输 | SSL/TLS 证书 |
| 必须关闭调试模式 | 生产环境禁止开启 debug | 环境变量控制 |
| 必须定期更新依赖 | 修复已知安全漏洞 | 定期扫描依赖漏洞 |

## 十一、写代码模式安全执行清单

> 写代码模式生成代码时，必须同步执行以下安全规范。

| 检查项 | 是否执行 | 说明 |
|--------|----------|------|
| SQL查询是否使用参数化查询 | ✅ 必须执行 | 禁止字符串拼接 |
| 密码是否使用BCrypt/Argon2哈希 | ✅ 必须执行 | 禁止明文或弱哈希 |
| Token是否设置过期时间 | ✅ 必须执行 | 禁止永久有效 |
| Cookie是否设置HttpOnly | ✅ 必须执行 | 防止JS读取 |
| 所有接口是否有输入验证 | ✅ 必须执行 | 类型、长度、范围校验 |
| 日志是否禁止敏感信息 | ✅ 必须执行 | 禁止记录密码、Token |
| API返回是否脱敏敏感字段 | ✅ 必须执行 | 手机号、身份证号脱敏 |
| 错误响应是否隐藏技术细节 | ✅ 必须执行 | 禁止暴露堆栈、SQL |
| 文件上传是否有白名单 | ✅ 必须执行 | 类型、大小限制 |
| 是否禁止硬编码敏感信息 | ✅ 必须执行 | 密码、密钥、Token |
