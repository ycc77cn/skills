# 代码开发标准流程 七步（dev-workflow）

代码开发的强制流程技能，把「怎么干」固定成七步，约束 AI 按序执行、不跳步。

## 用途

每次涉及写代码、改代码、修 bug、加功能、重构，都按这套流程走。上一步未通过，禁止进入下一步。

## 覆盖范围

| 步骤 | 内容 | 目的 |
| --- | --- | --- |
| 第 0 步 | 先聊再动手 | 需求对齐，确认范围与验收标准 |
| 第 1 步 | 备份 | 改动前留快照，保证可回退 |
| 第 2 步 | 改码 | 按需求实施，改动最小化 |
| 第 3 步 | 启动双端 | 前端后端都要跑起来，不只跑一端 |
| 第 4 步 | 浏览器实测 | 真实页面验证，不靠推测 |
| 第 5 步 | 白盒审计 | 通读改动，查遗漏与隐患 |
| 第 6 步 | 逐项验证 | 对照需求清单一条条验 |

### 贯穿纪律

- **数据纪律**：任何改动可逆，先备份后动手；
- **卡住纪律**：同一问题反复失败即停手通报，不硬试；
- **收尾纪律**：临时文件、调试代码、测试脚本用完清理；
- **完成标准**：需求逐条验过、无遗留报错，才算完成。

另附流程速查表，便于快速对照当前处于哪一步。

## 内部结构

```text
开发标准流程-七步/
├── SKILL.md        # 完整七步流程、贯穿纪律、完成标准、速查表
└── README.md       # 本文件
```

## 调用方式

由 AI 工具按 `SKILL.md` 的 `description` 自动触发。典型触发语句：写代码、改代码、修 bug、加功能、重构、优化。

## 能力边界

1. 只管流程与纪律，不替代具体技术方案；
2. 不适用于纯文档编写、纯问答类任务；
3. 完整跑流程开销较大，小改动可按实际裁剪，但备份与验证两步不可省。
